# Implementation Plan - Optimistic UI Updates for Archiving, Unarchiving, and Deleting

We are implementing Optimistic UI Updates for appointment status transitions (archiving, unarchiving, and deleting/cancelling). This ensures the UI updates instantly, moving items between local lists in 0ms, while remote API calls proceed in the background. If an API call fails, the state is rolled back automatically.

## User Review Required

> [!NOTE]
> All updates will be managed directly in `AppointmentProvider`. The UI components will not need any changes, as they already watch the lists (`appointments`, `archivedAppointments`, `trashedAppointments`) and listen to provider notifications.

## Proposed Changes

### Features / Appointments / Providers

#### [MODIFY] [appointment_provider.dart](file:///Users/hussain/Documents/sijilli/lib/features/appointments/providers/appointment_provider.dart)
Modify `archiveInvitation`, `unarchiveInvitation`, and `deleteInvitation` with backing variables, instant state transitions, and rollback mechanisms upon failure:

##### 1. `archiveInvitation(String appointmentId)`
- Find `indexBefore` and get `appointment` from `_appointments`.
- **Optimistic Transition**:
  - Remove from `_appointments`.
  - Copy `appointment` and set `postStatus` to `PostStatus.archived` in its `viewerRecord` invitation.
  - Insert into `_archivedAppointments` and sort both lists.
  - Trigger `notifyListeners()`.
- **Network Call**: Update invitation postStatus to `PostStatus.archived` via `_invitationService`.
- **On Success**:
  - Save cached list locally via `_localDb.saveAppointments(_appointments)`.
  - Fetch archived list in the background via `fetchArchivedAppointments()`.
- **On Failure**:
  - Roll back: remove from `_archivedAppointments`, insert back into `_appointments` at `indexBefore`, and sort lists.
  - Save error message and notify listeners.

##### 2. `unarchiveInvitation(String appointmentId)`
- Find `indexBefore` and get `appointment` from `_archivedAppointments`.
- **Optimistic Transition**:
  - Remove from `_archivedAppointments`.
  - Copy `appointment` and set `postStatus` to `PostStatus.published` in its `viewerRecord` invitation.
  - Insert into `_appointments` and sort both lists.
  - Trigger `notifyListeners()`.
- **Network Call**: Update invitation postStatus to `PostStatus.published` via `_invitationService`.
- **On Success**:
  - Save cached list locally via `_localDb.saveAppointments(_appointments)`.
  - Fetch active list in the background via `fetchAppointments()`.
- **On Failure**:
  - Roll back: remove from `_appointments`, insert back into `_archivedAppointments` at `indexBefore`, and sort lists.
  - Save error message and notify listeners.

##### 3. `deleteInvitation(String appointmentId)`
- Find `indexBefore` and `listType` (from either `_appointments` or `_archivedAppointments`).
- Get `appointment` from the matching index.
- **Optimistic Transition**:
  - Remove from `_appointments` (or `_archivedAppointments`).
  - Copy `appointment` and set `postStatus` to `PostStatus.trash` in its `viewerRecord` invitation (and status to `deletedAfterAccept` if accepted and user is a guest, or mark global cancel if host).
  - Insert into `_trashedAppointments` and sort lists.
  - Trigger `notifyListeners()`.
- **Network Call**: Cancel appointment if Host/Admin via `_apptService`, or update invitation status to `PostStatus.trash` if Guest via `_invitationService`.
- **On Success**:
  - Save cached list locally via `_localDb.saveAppointments(_appointments)`.
  - Fetch active/archived/trashed lists in the background to ensure sync.
- **On Failure**:
  - Roll back: remove from `_trashedAppointments`, insert back into `_appointments` (or `_archivedAppointments`) at `indexBefore`, and sort lists.
  - Save error message and notify listeners.

### Manual Verification

2. Tap "Archive" on an appointment. Verify it disappears from the active list instantly (0ms) and is moved to the Archive tab.
3. Tap "Unarchive" on an archived appointment. Verify it returns to the active list instantly.
4. Tap "Delete" on an appointment. Verify it disappears instantly and is moved to Trash.
5. Simulate offline mode (e.g., toggle flight mode or disable network connection) and perform these actions:
   - Verify the action still completes instantly on the UI.
   - Verify that after the network timeout/failure, the UI rolls back the action and restores the appointment to its original list, displaying a snackbar error message.
